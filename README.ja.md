# ECHELON

[English](README.md) | **日本語**

> 見下ろし型の大規模分隊戦術ゲーム。正確な指揮系統の**どの階級にも入り込んで**指揮でき、
> それ以外はすべてAIが動かします。
> (仮称: *見下ろし型・大規模分隊戦術ゲーム(仮)*)

ECHELON は、*Full Spectrum Warrior* の「射撃と移動」の分隊ロジック、PS2版 *Star Wars:
Battlefront* の同時多発的な大規模戦闘、*Battlefield 2: Modern Combat* の「どのユニットにも
乗り換えられる」ホットスワップ、そして *Door Kickers* の見下ろし型の視界・被害モデルを、
5階層の指揮系統(中隊 → 小隊 → 分隊 → 火力班 → 兵士)の上で組み合わせたゲームです。

**現在の段階: 遊べるプロトタイプ。** 7つの試作モックを `src/` の下で1つのゲーム状態・1つの
シミュレーションループに統合しました。5つの階層すべてが同じ世界の上で、ブラウザ内で動きます。

![旧市街での小隊視点の戦闘。BLUEの分隊が中央の拠点へ集まり、HUDには指揮系統ツリー、兵力、拠点の確保進行が表示される](docs/media/overview.gif)

*小隊長の目で戦場を見ているところ。全ユニットがAI制御で、パネルには指揮系統・兵力・拠点の
確保進行がリアルタイムに表示されます。*

## 本作の特徴

### 兵士ではなく、指揮系統の「席」に座る

中隊・小隊・分隊のどれでも選んで、その席に座れます。ほかはすぐにAIが引き続き動かし、
プレイヤーに許されるのは**AIが出せる命令と同じもの、それ以上でもそれ以下でもありません**
(仕様 §4)。右クリックで移動命令、席はいつでも返せます。

![1分隊にホットスワップ。カメラが分隊に寄り、バナーが MANUAL に変わり、右クリックの移動命令で分隊が経路をたどる](docs/media/hotswap.gif)

*分隊にホットスワップし、残りの部隊が戦っているあいだに移動命令で操る。
オレンジの菱形が目的地、線が経路です。*

### 指揮は「情報の劣化」込み — 見えない物は見えない

兵士は目で見て、火力班長は班員の視界の合算を得て、分隊長は麾下の火力班の合算を得ます。
それより上は無線のみで、遅れ、薄れ、1ホップごとに粗くなります。中隊の「見えている戦況」は
小隊より確実に古く、あいまいです。視点を 中隊 / 小隊 / 分隊 / 神 と切り替えると、
戦場の霧が変わるのが分かります。

### 戦場全体から、兵士1人まで

カメラは戦場全体から接敵点へ寄っていきます。寄った先には、個々の兵士、火力班、曳光弾、
制圧された兵・負傷した兵の印が見えます。すべて演出ではなく、シミュレーションされた実体です。

![戦場全体から激戦地へカメラが寄っていく。個々の兵士、曳光弾、負傷者の印が見えてくる](docs/media/firefight.gif)

*盤面全体から接敵点へ寄っていく。*

### 拠点確保

拠点は、その中に立つことで確保します。確保が進むあいだ、中心から**薄い青の円が広がり**、
完了するとリングが確保した側の色に変わります。両軍が拠点内にいると、カウントは止まります(コンテスト)。

![BLUEの火力班が拠点に入り、薄い青の円がリングいっぱいまで広がって確保が完了する](docs/media/capture.gif)

*BLUEの火力班が1室ぶんの拠点を押さえ、確保の円が満ちていく。*

### 負傷者は消えない、運ばれる

被弾 → 負傷 → 応急処置 → 2名または4名の担架班が収容 → 負傷者集合点へ搬送 (仕様 §9)。
搬送中の担架要員は武器を使えず、そのぶん分隊は弱くなります。

![REDの担架班が負傷兵を運ぶ。水色のリングが担架要員](docs/media/casevac.gif)

*4名の担架班(水色のリング)が負傷兵を負傷者集合点へ運ぶ。*

### 路地戦から無人地帯まで、5つの盤面

見通しの短い市街戦、渡ること自体が問題になる幅40mの大通り、段違いの新市街、対峙する塹壕線、
そして挙動比較の基準になる格子状の街区。中隊規模のシナリオは**片側91名**までを展開します。

## 実装済みの機能

以下はすべて今動きます。§番号は設計仕様のものです。

- **5つの階層** (§2)。小隊本部・中隊本部にも実体があるので、指揮官が倒れると
  指揮が下へ継承されます (§12)。
- **階層ごとの情報** (§5)。上記のとおり。
- **移動** (§6)。通常移動 / 警戒しつつ移動 / 交互躍進。真実ではなく、指揮官の「見えている戦況」から
  選ばれます。隊形は周囲の通路幅から Tier 1〜4 が自動で選ばれます。
- **戦闘と後送 (CASEVAC)** (§8, §9)。被弾 → 戦死/負傷 → 出血 → 応急処置 → 担架搬送 →
  負傷者集合点 → 後送アセット → 同じ職種(MOS)での補充まで一貫して動きます。
- **CQB(屋内戦)** (§7)。建物・扉、屋内0.3m / 屋外1.0m の航行グリッド、
  Battle Drill 6 の手順: 積み → 突破 → 掃討 → 再編成。
- **§12 の全体**: 指揮継承、士気崩壊、拠点確保、勝敗判定。
- **ホットスワップ** (§4)。上記のとおり、どの階層にも。
- **挟撃・側面機動** (§6, `[v7.0]`)。分隊長は交戦のあいだ、基準班/機動班の役割を固定して
  脅威を中心とした弧で機動班を回します。小隊長は1個分隊で敵を拘束し、別の分隊を敵線の**端**へ回します。
- **盾持ち** (§14, `[v7.0]`, 編成オプション)。各火力班の小銃手1名が防弾盾と拳銃に持ち替え、
  班は盾の後ろに密集して進みます。
- **増援** (§11, `[v7.0]`, 編成オプション, 数値は暫定)。最上位の指揮官が要請し、遅れて到着して
  既存の指揮系統に加わります。
- **LLMの席** (§4, `[v7.0]`)。LM Studio 経由のローカルLLMが中隊/小隊/分隊指揮官の席に座れます。
  見えるのはその指揮官の「認識」だけで、人間と同じ命令だけを出します。

## はじめかた

[Node.js](https://nodejs.org/)(LTS)が必要です。

```sh
npm install
npm run dev      # 起動後 http://localhost:5173/ をブラウザで開く
```

戦闘は**立案フェーズ**(時間停止中)から始まります。作戦を読み、開始ボタンを押してください。
左のパネルで**盤面・視点・陣営**を切り替え、右の指揮系統ツリーから操作するユニットを選びます。
コードに慣れていない方は、[`docs/はじめかた.md`](docs/はじめかた.md)(Windows向けの手順書)をどうぞ。

| コマンド | 内容 |
|---|---|
| `npm run dev` | アプリを起動(ローカルのポートで開く) |
| `npm test` | ヘッドレスのシミュレーションテストを実行 |
| `npm run balance` | MOSのバランス表を表示(`npm run balance 5000` で戦闘回数を増やす) |
| `npm run llm` | ローカルLLM(LM Studio)に1階層を指揮させる(ヘッドレス戦闘。`-- --mock` でLLM無しの結線確認) |
| `npm run typecheck` | TypeScript の型検査 |
| `npm run lint` | ESLint |
| `npm run build` | 型検査 + 本番ビルド |

構成: Vite + React + TypeScript、見下ろし描画は three.js、UI状態は Zustand。

## テストが守る2つの不変条件

**戦力の対称性 (§2/§13)** は、勝率の統計ではなく、*陣営ラベルを入れ替えて結果がぴったり反転する
ことを確かめる*ことで検証します。§13 の主張はコードについてのもの(プレイヤーに有利な分岐が
無い)で、完全な反転は、シミュレーションが `side` を一切読んでいない証明になります。勝率だと
混ざってしまう地形の有利とも切り分けられます。バランス検証も同じ発想で、両陣営に同じ乱数列と
同一の編成を与えると、戦闘は完全な相打ちで終わらなければなりません。

**決定性。** 同じシードなら同じ結果。`src/sim/` 内では `Math.random` と `Date.now` を禁止し、
乱数は陣営ごとに1本のシード付き乱数列だけを通します。
